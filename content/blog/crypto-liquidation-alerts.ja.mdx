# 仮想通貨のロスカット通知：ポジションが飛ぶ前に、電話で叩き起こす

午前3時に、サイレントなプッシュ通知として届くロスカット・リスク通知には何の価値もありません。眠っている間に証拠金維持率がロスカット水準へ向かって落ちているとき、意味を持つ唯一の通知は、電話のようにスマホを鳴らし、おやすみモードを突き破ってくるものだけです。本記事では、まさにそれを構築する方法を解説します——TradingView や監視サービスからのロスカット・リスク信号を、[Echobell](https://apps.apple.com/app/apple-store/id6743597198?pt=128151925&ct=blog-crypto-liquidation-alerts-ja&mt=8) で電話に変えるのです。

ロスカットの連鎖は、めったに起きない周縁的なリスクではありません。2025年10月10日〜11日、単日のデリバティブ・スクイーズが市場全体で **190億ドル**を超えるレバレッジ・ポジションを強制決済しました——これは仮想通貨史上最大のロスカット事象です——トランプ大統領が中国からの輸入品に100%の関税を課すと発表した後、およそ **160万件**の取引口座が吹き飛びました（[CoinGecko](https://www.coingecko.com/learn/october-10-crypto-crash-explained)、[CoinDesk Research](https://www.coindesk.com/research/market-spotlight-the-19-billion-liquidation-that-shook-crypto)）。そのうち約70%——およそ69.3億ドル——はわずか40分の間に発生し、UTC 21:15 の1分間だけで32.1億ドルが蒸発しました。2025年全体では、CoinGlass が集計したロスカット総額は **1500億ドル**を超え、1日あたり平均4億〜5億ドルに達しました（[Bitcoinist（CoinGlass を引用）](https://bitcoinist.com/crypto-liquidations-150-billion-2025-coinglass/)）。

連鎖を止めることはできません。しかしレバレッジを使って取引しているなら、それが起きたときに自分が起きていることは保証できます。

## なぜサイレント通知ではロスカット・リスクに勝てないのか

**ロスカット警告は、あなたを中断させられなければ警告ではありません。** 標準的なスマホのプッシュ通知は、iOS の集中モード、おやすみモード、睡眠スケジュールによって消音されます——それはまさに、日曜深夜のフラッシュクラッシュが始まるときにあなたが置かれている状態です。取引所アプリのプッシュやメール通知は、維持証拠金が少しずつ枯れていく間、未読のまま積み上がっていきます。

Echobell は、この一点を解決するために存在します。Webhook やメールを電話に変えるのです——実際に鳴り、振動する着信として、家族からの電話のように iOS の集中モードやおやすみモードを迂回します（[重要な通知のために iOS 集中モードを突破する](/blog/how-to-bypass-ios-focus-mode-for-critical-alerts)を参照）。あなたの代わりにトレードはしませんし、取引所の残高にも接続しません。それは、通知を「寝過ごせないもの」にする配信レイヤーです。

## 仮想通貨のロスカットは実際どう起きるのか

**あなたがロスカットされるのは、証拠金維持率が取引所の維持基準を割ったときであって、価格がキリのいい数字に触れたときではありません。** Binance のポートフォリオマージン方式では、口座は統合維持証拠金率（uniMMR）で測られ、調整後純資産を保有ポジションが要求する維持証拠金で割って算出します。この比率が **105%** を下回ると、ロスカット・エンジンが口座を引き継ぎ、負債を賄うために資産を強制売却します。いったん始まると、止まることも逆転することもありません（[Binance：uniMMR](https://www.binance.com/en/support/faq/what-is-the-unified-account-maintenance-margin-ratio-unimmr-and-how-is-it-calculated-4868b2f1aa6c4d08af973328462bb0bd)）。

分離マージンのポジションでは、同じ考え方が単一の**ロスカット価格**に集約されます。残った証拠金が維持要件を賄えなくなる水準です。Binance は、参入価格・ポジションサイズ・レバレッジ・維持証拠金率に依存する具体的な計算式を公開しています（[Binance：ロスカット価格の計算方法](https://www.binance.com/en/support/faq/how-to-calculate-margin-liquidation-price-f6b010588e55413aa58b7d63ee0125ed)）。他の取引所も、独自の証拠金ティアを持つ同様の仕組みを採用しています。

実務上の要点はこうです。**あなたはすでに自分のロスカット価格を知っているか、算出できます。** その数字こそ、通知したいトリガーです——理想的にはバッファを持たせ、エンジンが火を噴いた後ではなく、まだ証拠金を足したりポジションを減らしたりする時間があるうちに電話が鳴るようにしましょう。

## 取引所はロスカット前に Webhook を送ってくれるのか？

**たいていは送ってくれません——これが設計上、回り込むべき正直な限界です。** 主要な取引所は、証拠金維持率が下がったときに任意の URL へアウトバウンドの Webhook を送りません。自社アプリ内とメールで通知するだけです。したがって Echobell は、あなたの Binance や Bybit の口座に直接サブスクライブできません。ポジションを見張って Webhook を発火させる「別の何か」が必要です。現実的な信号源は3つあります。

1. **価格アラート**：ロスカット水準（またはその上の安全バッファ）に設定、Webhook 対応のチャートプラットフォームから。
2. **市場監視サービス**：もともと Webhook アクションに対応しているもの。
3. **自作スクリプト**：取引所 API をポーリングして自分の証拠金維持率を取得。

3つとも行き着く先は同じです。あなたの Echobell チャンネルの Webhook URL への HTTP リクエストが、スマホを鳴らします。

## Echobell でロスカット電話通知を設定する

まず、あなたを鳴らすチャンネルを作ります。

### ステップ1 —— Calling（着信）チャンネルを作成

Echobell をダウンロードし、新しいチャンネルを作成して、通知タイプを **Calling（着信）** に設定します——これがサイレントなプッシュではなく電話を鳴らす鍵です。チャンネル詳細から Webhook URL をコピーします。`https://hook.echobell.one/t/<channel-token>` のような形式です。これは秘密として扱ってください。より穏やかな情報系の通知用には、別途 **Time-Sensitive（時間指定）** または **Normal（通常）** チャンネルを用意します（[通知タイプ](/docs/notification)を参照）。

### ステップ2 —— トリガー源を選ぶ

**選択肢A —— TradingView の価格アラート（最も簡単）。** 有料の TradingView プランでチャートを開き、「価格が下抜け」であなたのロスカット・バッファ水準を条件にアラートを作成し、**Webhook URL** アクションを選んで Echobell の URL を貼り付けます。アラートメッセージを、Echobell がテンプレート化できる JSON に設定します。例えば：

```json
{
  "title": "⚠️ ロスカット・リスク：{{ticker}}",
  "message": "{{ticker}} が {{exchange}} で {{price}} に到達 —— 証拠金バッファを割りました"
}
```

詳細な手順：[TradingView 連携](/docs/trader/tradingview)。Webhook アラートには有料の TradingView プランが必要な点にご注意ください。

**選択肢B —— 仮想通貨の監視サービス。** [Cryptocurrency Alerting](/docs/trader/cryptocurrency-alerting) のようなツールは、価格・出来高・オンチェーンのイベントを監視し、条件が発火したときに Webhook を呼び出せます。その Webhook を Echobell チャンネルに向ければ、たとえば BTC があなたのポジションを危険にさらす水準を割ったときに、電話がかかってきます。

**選択肢C —— 自作の証拠金維持率モニター。** 代替となる価格ではなく実際の証拠金維持率で通知したい場合は、取引所の API をポーリングして口座の維持証拠金率を取得し、あなたが設定した閾値を割ったとき（例えば、105% のロスカット点よりずっと手前の uniMMR 130% 未満）に Echobell へ POST する小さなスクリプトを走らせます。HTTP クライアントを持つ言語なら何でも動きます——[Webhook ガイド](/docs/webhook)がペイロードとテンプレート変数を解説しています。

### ステップ3 —— テストする

手動でアラートを発火させます——テスト Webhook を送るか、一時的に即発火する TradingView 条件を設定します。数秒以内にスマホが鳴るはずです。おやすみモードをオンにしてテストし、集中モードを突き破ることを確認してください。

## Echobell にできること、できないこと

実際にお金がかかっている場合、この点を明確にすることは、ダウンしたサーバーのとき以上に重要です。

**Echobell にできること：**

- Webhook やメールを、鳴る電話・時間指定通知・通常プッシュに変える。
- Calling タイプの通知で iOS の集中モードとおやすみモードを突破する。
- チャンネルを共有し、トレーディングデスク全体が同じ電話を受け取れるようにし、最初の人が応答しない場合は繰り返し呼び出す。

**Echobell にできないこと：**

- あなたの取引所口座に接続したり、残高を読んだり、実際の証拠金維持率を独力で知ったりすること。トリガー源が送ってきた内容しか知りません。
- 証拠金を足す、ポジションを閉じる、注文をキャンセルすること。これは通知レイヤーであって、トレーディングボットでもリスク管理エンジンでもありません。
- ストップロスの代替になること。通知はあなたのスマホ・電波・反応速度に依存します。一方、取引所内のストップロスや削減専用注文は、あなたが不在でも執行されます。**通知は取引所内のリスク管理と併用してください。決して置き換えないでください。**

もしあなたのリスク計画のすべてが「通知が来たら間に合ううちに証拠金を足す」だけなら、あなたは電池切れひとつでロスカットまで一歩です。正しいメンタルモデルはこうです。取引所内のストップロスがあなたの自動防御であり、電話通知は、機械が代わりに判断できない瞬間のための人間側の最終防衛線です。

## よくある質問

### Echobell はポジションのロスカットを防げますか？

いいえ。Echobell は通知を配信するもので、証拠金を足したりポジションを閉じたりはできません。ロスカットを防げるのは、取引所内のストップロス、削減専用注文、またはあなた自身の手動操作だけです。Echobell の役割は、あなたが間に合ううちに気づけるようにすることです。

### Echobell は Binance、Bybit、OKX に直接接続しますか？

いいえ。Echobell は Webhook とメールを受け取りますが、あなたの取引所口座にはログインしません。すでにポジションを見張っているトリガー源——TradingView アラート、監視サービス、または自作の API スクリプト——を経由して接続し、それが Webhook を Echobell に送ります。

### アラートの閾値はどう設定すべきですか？

ロスカット点そのものではなく、実際のロスカット価格や維持基準より上のバッファに対して通知しましょう。一般的なやり方は、証拠金維持率が警告水準に近づいたとき（例えば Binance の uniMMR が約 130%、ロスカット・トリガーは 105%）に通知し、反応する時間を確保することです。ロスカット価格は取引所の公開式で計算してください。

### スマホがおやすみモードでも電話は届きますか？

届きます。Echobell の Calling 通知タイプは、iOS の集中モードとおやすみモードを鳴らし抜けるよう設計されており、連絡先からの繰り返しの着信が通過する仕組みに似ています。頼りにする前に、おやすみモードを有効にしてテストしてください。

### 有料の TradingView プランは必要ですか？

TradingView の Webhook アラートアクションには必要です——Webhook には有料プラン（Pro/Pro+/Premium）が要ります。持っていない場合は、Webhook 対応の監視サービスや、自作スクリプトをトリガー源に使ってください。

### トレーディングチーム全員に通知できますか？

できます。Echobell チャンネルをチームメンバーと共有すれば、購読している全員が通知を受け取ります。誰かが応答するまで呼び出し続けるよう、繰り返し動作を設定できます。
